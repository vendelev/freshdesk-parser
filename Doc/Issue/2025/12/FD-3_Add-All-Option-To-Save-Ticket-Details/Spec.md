# Спецификация: Добавление опции --all для сохранения детальной информации о всех задачах

## Описание проблемы/потребности

В рамках задачи FD-2 была реализована функциональность сохранения детальной информации о задачах из Freshdesk, но опция `--all` для сохранения деталей всех задач пока не реализована. Текущая реализация позволяет сохранять детали только для одной конкретной задачи через параметр `--ticket-id`.

Необходимо реализовать опцию `--all`, которая будет сохранять детальную информацию для всех задач, которые были ранее загружены и сохранены в бекапах системы.

---

## Функциональные требования

### FR1. Обработка всех задач из существующих бекапов

- **FR1.1**: Система должна сканировать существующие бекапы задач для получения списка всех задач
- **FR1.2**: Система должна обрабатывать все задачи из найденных бекапов
- **FR1.3**: Система должна пропускать задачи, для которых уже существует детальная информация, если не указана опция `--force`

### FR2. Опция --force для принудительной перезаписи

- **FR2.1**: Система должна поддерживать опцию `--force` для принудительной перезаписи существующих деталей задач
- **FR2.2**: При указании `--force` система должна перезаписывать детальную информацию для всех задач, независимо от наличия существующих файлов

### FR3. Информирование пользователя о процессе

- **FR3.1**: Система должна выводить прогресс выполнения при обработке множества задач
- **FR3.2**: Система должна отображать количество успешно обработанных, пропущенных и ошибочных задач
- **FR3.3**: Система должна логировать ошибки для каждой задачи отдельно, продолжая обработку остальных задач

---

## Нефункциональные требования

### NFR1. Производительность

- **NFR1.1**: Система должна обрабатывать большие объемы задач с учетом rate limiting Freshdesk API
- **NFR1.2**: Система должна реализовать экспоненциальный backoff при достижении лимитов API

### NFR2. Надежность

- **NFR2.1**: При ошибке обработки одной задачи система должна продолжать обработку остальных задач
- **NFR2.2**: Система должна корректно обрабатывать ситуации, когда бекапы отсутствуют или повреждены

### NFR3. Безопасность

- **NFR3.1**: Система должна корректно обрабатывать и логировать ошибки без раскрытия чувствительной информации

## Модель предметной области

### Entity и Value Objects

**ProcessedTicket (Обработанная задача)**
- `ticket_id`: int — ID задачи
- `status`: string — статус обработки (success|skipped|failed)
- `file_path`: string|null — путь к файлу деталей
- `error_message`: string|null — сообщение об ошибке

**ProcessingSummary (Сводка обработки)**
- `total_tickets`: int — общее количество задач
- `processed`: int — количество обработанных задач
- `skipped`: int — количество пропущенных задач
- `failed`: int — количество задач с ошибками
- `start_time`: datetime — время начала обработки
- `end_time`: datetime|null — время окончания обработки

### Внешние зависимости

- **Freshdesk API**: Источник детальной информации о задачах

## Сценарии использования

### Use Case 1: Сохранение деталей для всех задач без перезаписи

**Актор**: Разработчик/администратор (в консоли)

**Основной сценарий**:
1. Пользователь выполняет команду `php artisan backup:ticket-details --all`
2. Система сканирует существующие бекапы для получения списка задач
3. Система последовательно обрабатывает каждую задачу:
   - Если детали задачи уже существуют - пропустить
   - Если деталей нет - получить и сохранить детальную информацию
4. Система выводит сводку обработки

### Use Case 2: Сохранение деталей для всех задач с принудительной перезаписью

**Актор**: Разработчик/администратор (в консоли)

**Основной сценарий**:
1. Пользователь выполняет команду `php artisan backup:ticket-details --all --force`
2. Система сканирует существующие бекапы для получения списка задач
3. Система последовательно обрабатывает каждую задачу:
   - Получить и сохранить детальную информацию, перезаписывая существующие файлы
4. Система выводит сводку обработки

## Риски

### R1: Rate limiting Freshdesk API

**Описание**: Обработка большого количества задач может привести к превышению лимитов API Freshdesk.

**Смягчение**: Реализовать экспоненциальный backoff, учитывать Rate-Limit headers.

### R2: Длительное время выполнения

**Описание**: Обработка всех задач может занять значительное время.

**Смягчение**: Отображать прогресс выполнения, обеспечить возможность прерывания.

### R3: Отсутствие бекапов

**Описание**: При отсутствии бекапов система не сможет получить список задач.

**Смягчение**: Выводить понятное сообщение об ошибке.

---

## Критерии приемки

### CA1: Корректная обработка всех задач

- [ ] Система успешно обрабатывает все задачи из существующих бекапов
- [ ] Система пропускает задачи с существующими деталями (без --force)
- [ ] Система перезаписывает детали при указании --force

### CA2: Обработка ошибок

- [ ] При ошибке обработки одной задачи система продолжает обработку остальных
- [ ] Система выводит сводку с количеством успешно обработанных, пропущенных и ошибочных задач

### CA3: Прогресс выполнения

- [ ] Система отображает прогресс выполнения при обработке множества задач
- [ ] Система выводит финальную сводку по завершении обработки

---

## Не входит в реализацию

- **Автоматическое выполнение по расписанию**: Команда выполняется только вручную
- **Параллельная обработка задач**: Задачи обрабатываются последовательно
- **Фильтрация задач по критериям**: Обрабатываются все задачи из бекапов
- **Скачивание вложений**: Система сохраняет только информацию о вложениях, не сами файлы
