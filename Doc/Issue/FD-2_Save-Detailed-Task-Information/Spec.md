# Спецификация: Сохранение детальной информации о задачах из Freshdesk

## Описание проблемы/потребности

После реализации бекапа списка задач (FD-1) требуется создать функциональность для сохранения детальной информации о каждой задаче. Детальная информация включает полные данные задачи, переписку (conversations), вложения (attachments) и другие связанные данные, которые не доступны в списке задач. Это необходимо для:

- Полного резервного копирования всех данных задач
- Обеспечения возможности анализа переписки и вложений
- Создания полного архива для аудита и compliance
- Подготовки данных для миграции или интеграции с другими системами

---

## Функциональные требования

### FR1. Получение детальной информации из Freshdesk API

- **FR1.1**: Система должна получать детальную информацию о задаче по ее ID через Freshdesk API (/api/v2/tickets/{id})
- **FR1.2**: Система должна получать все доступные поля задачи, включая расширенные данные (conversations, attachments, time_entries и т.д.)
- **FR1.3**: Система должна корректно обрабатывать пагинацию при получении conversations и других связанных данных
- **FR1.4**: Система должна поддерживать получение детальной информации для одной задачи или для списка задач

### FR2. Сохранение детальной информации

- **FR2.1**: Система должна сохранять детальную информацию каждой задачи в отдельный JSON файл
- **FR2.2**: Структура хранения: директория для детальной информации задач (например, storage/tickets/detail/)
- **FR2.3**: Имя файла: {ticket_id}.json
- **FR2.4**: Файл должен содержать полную детальную информацию задачи с метаданными о времени сохранения
- **FR2.5**: Система должна обновлять существующие файлы при повторном сохранении той же задачи

### FR3. Инициирование сохранения детальной информации

- **FR3.1**: Сохранение должно быть доступно через консольную команду Laravel
- **FR3.2**: Система должна предоставить команду `php artisan backup:ticket-details` для сохранения детальной информации
- **FR3.3**: Команда должна поддерживать опции: --ticket-id для конкретной задачи, --all для всех задач из списка
- **FR3.4**: Команда должна выводить статус выполнения и метаинформацию о сохраненных данных
- **FR3.5**: Команда должна поддерживать флаг `--help` с описанием синтаксиса

### FR4. Обработка ошибок

- **FR4.1**: При недоступности Freshdesk API система должна возвращать информативную ошибку
- **FR4.2**: При ошибках записи на диск система должна логировать ошибку и продолжать обработку других задач
- **FR4.3**: Система должна логировать все ошибки для диагностики
- **FR4.4**: При частичном сбое система должна сохранять успешно полученные данные

## Нефункциональные требования

### NFR1. Производительность

- **NFR1.1**: Сохранение детальной информации одной задачи должно завершаться в разумное время (не более 30 секунд)
- **NFR1.2**: Система должна корректно обрабатывать Freshdesk API rate limits с экспоненциальным backoff
- **NFR1.3**: Параллельная обработка нескольких задач должна быть ограничена для соблюдения rate limits

### NFR2. Надежность

- **NFR2.1**: Система должна корректно обрабатывать потери соединения с Freshdesk API
- **NFR2.2**: При невозможности получить детальную информацию для одной задачи, система должна продолжать обработку других задач
- **NFR2.3**: Частично полученные данные должны быть сохранены с отметкой о неполноте

### NFR3. Безопасность

- **NFR3.1**: API ключ Freshdesk должен храниться в переменных окружения (.env файл)
- **NFR3.2**: API ключ не должен логироваться или попадать в статус-отчеты
- **NFR3.3**: Детальная информация должна содержать только те данные, которые доступны через API с текущим уровнем доступа

### NFR4. Масштабируемость

- **NFR4.1**: Система должна корректно обрабатывать большое количество задач с детальной информацией
- **NFR4.2**: Файловая система должна справляться с размерами файлов детальной информации (предполагаемый размер JSON для одной задачи с conversations ~ 1-5 МБ)

### NFR5. Удобство использования

- **NFR5.1**: Процесс инициирования сохранения должен быть простым и понятным
- **NFR5.2**: Команда должна выводить понятные сообщения об ошибках и статус выполнения
- **NFR5.3**: Команда должна поддерживать флаг `--help` с описанием синтаксиса команды

## Модель предметной области

### Entity и Value Objects

**DetailedTicket (Детальная задача)** - расширение Ticket из FD-1
- Все поля из Ticket (FD-1)
- `conversations`: array — массив переписок (replies, notes, forwards)
- `attachments`: array — массив вложений с ссылками на скачивание
- `time_entries`: array — записи времени работы над задачей
- `custom_objects`: array — пользовательские объекты
- `shared_assets`: array — общие ресурсы
- `sla_policy`: object — политика SLA
- `stats`: object — статистика задачи
- `tags`: array — расширенный список тегов
- `cc_emails`: array — email адреса в копии
- `fwd_emails`: array — пересланные email
- `reply_cc_emails`: array — email для ответов в копии
- `ticket_cc_emails`: array — email копии задачи
- (и другие поля согласно детальному API Freshdesk)

**Conversation (Переписка)**
- `id`: int — уникальный идентификатор
- `body`: string — текст сообщения
- `body_text`: string — текст без HTML
- `user_id`: int — ID пользователя
- `support_email`: string — email поддержки
- `source`: int — источник (1=email, 2=portal, 3=phone, etc.)
- `ticket_id`: int — ID задачи
- `created_at`: datetime — дата создания
- `updated_at`: datetime — дата обновления
- `private`: bool — приватное сообщение
- `attachments`: array — вложения в сообщении

**Attachment (Вложение)**
- `id`: int — уникальный идентификатор
- `name`: string — имя файла
- `content_type`: string — MIME тип
- `size`: int — размер в байтах
- `created_at`: datetime — дата создания
- `updated_at`: datetime — дата обновления
- `attachment_url`: string — URL для скачивания

**DetailBackup (Детальный бекап)**
- `ticket_id`: int — ID задачи
- `saved_at`: datetime — дата/время сохранения
- `file_path`: string — путь к файлу
- `status`: string — статус (success|partial|failed)
- `error_message`: string | null — сообщение об ошибке

## Сценарии использования

### Use Case 1: Сохранение детальной информации для всех задач

**Актор**: Разработчик/администратор (в консоли)

**Основной сценарий**:
1. Пользователь выполняет команду `php artisan backup:ticket-details --all`
2. Система получает список всех задач из бекапа FD-1
3. Система последовательно получает детальную информацию для каждой задачи
4. Система сохраняет детальную информацию в отдельные JSON файлы
5. Система выводит в консоль информацию о сохраненных данных (количество задач, время выполнения, статус)

**Альтернативный сценарий 1: Ошибка подключения к Freshdesk**:
- Система не может подключиться к Freshdesk API для одной задачи
- Система логирует ошибку и продолжает обработку следующих задач
- Система отмечает задачу как failed в отчете

**Альтернативный сценарий 2: Частичная ошибка получения данных**:
- Система получает основную информацию задачи, но не conversations
- Система сохраняет доступные данные с отметкой partial
- Система логирует причину неполноты

### Use Case 2: Сохранение детальной информации для конкретной задачи

**Актор**: Разработчик/администратор (в консоли)

**Основной сценарий**:
1. Пользователь выполняет команду `php artisan backup:ticket-details --ticket-id=12345`
2. Система получает детальную информацию для задачи 12345
3. Система сохраняет данные в файл 12345.json
4. Система выводит статус сохранения

### Use Case 3: Получение справки по команде

**Актор**: Разработчик/администратор (в консоли)

**Основной сценарий**:
1. Пользователь выполняет команду `php artisan backup:ticket-details --help`
2. Система выводит справку по команде, включая описание синтаксиса и опций

## Риски

### R1: Rate limiting Freshdesk API

**Описание**: Детальное получение данных требует больше запросов к API, что увеличивает риск превышения rate limits.

**Влияние**: Сохранение может быть прервано или сильно замедлено.

**Вероятность**: Высокая

**Смягчение**: Реализовать экспоненциальный retry с backoff, ограничить параллельные запросы, соблюдать Rate-Limit headers

### R2: Объем данных и время выполнения

**Описание**: Детальная информация включает conversations и attachments, что значительно увеличивает объем данных и время обработки.

**Влияние**: Длительное время выполнения, большой объем дискового пространства.

**Вероятность**: Высокая

**Смягчение**: Оптимизировать запросы, поддерживать частичное сохранение, мониторить прогресс

### R3: Изменение структуры API Freshdesk

**Описание**: Freshdesk может изменить структуру детального API или убрать некоторые поля.

**Влияние**: Сохранение может содержать неправильные или неполные данные.

**Вероятность**: Низкая

**Смягчение**: Поддерживать версионирование API, регулярно проверять совместимость, иметь fallback для основных полей

### R4: Недостаток прав доступа

**Описание**: API ключ может иметь недостаточные права для получения conversations или attachments.

**Влияние**: Детальная информация будет неполной.

**Вероятность**: Средняя

**Смягчение**: Четко документировать требуемые права, проверять доступ на начальном этапе, поддерживать частичное сохранение

### R5: Скачивание вложений

**Описание**: Attachments требуют дополнительных запросов для скачивания файлов.

**Влияние**: Увеличение времени и трафика, дополнительные rate limits.

**Вероятность**: Средняя

**Смягчение**: Опционально скачивать attachments, сохранять только URLs, поддерживать асинхронное скачивание

## Критерии приемки

### CA1: Успешное получение детальной информации

- [ ] При выполнении сохранения система получает полную детальную информацию задачи из Freshdesk API
- [ ] Детальная информация включает conversations, attachments и другие расширенные поля

### CA2: Корректное сохранение данных

- [ ] Детальная информация сохраняется в отдельные JSON файлы по ID задачи
- [ ] Все поля задачи полностью присутствуют в сохраненных данных
- [ ] Файлы содержат метаданные о времени сохранения

### CA3: Консольная команда

- [ ] Команда `php artisan backup:ticket-details --all` доступна и выполняется без ошибок
- [ ] Команда `php artisan backup:ticket-details --ticket-id=123` доступна для конкретной задачи
- [ ] Команда завершается с exit code 0 при успехе
- [ ] Команда выводит информацию о сохраненных данных (количество задач, время выполнения, статус)

### CA4: Обработка ошибок

- [ ] При недоступности Freshdesk система выводит понятное сообщение об ошибке
- [ ] При ошибке для одной задачи система продолжает обработку других задач
- [ ] Частично полученные данные сохраняются с соответствующей отметкой

### CA5: Безопасность

- [ ] API ключ хранится в переменных окружения
- [ ] API ключ не попадает в логи или вывод команды

### CA6: Справка команды

- [ ] Команда поддерживает флаг `--help`
- [ ] Флаг `--help` выводит описание синтаксиса команды и доступных опций

## Не входит в реализацию

- **Скачивание вложений**: Система сохраняет только URLs вложений, не скачивает файлы
- **История версий детальной информации**: Система перезаписывает существующие файлы без истории
- **Автоматическое выполнение по расписанию**: Сохранение выполняется только по команде
- **REST API**: Интеграция реализуется только через консольную команду, HTTP endpoints не требуются
- **Синхронизация изменений в реальном времени**: Система сохраняет детальную информацию на момент запроса
- **Восстановление данных из детальной информации**: Детальная информация — только для хранения, восстановление не требуется
- **Шифрование данных**: Данные сохраняются в открытом виде
- **Интеграция с облачными хранилищами**: Детальная информация хранится только в локальной файловой системе
- **Валидация данных**: Система не валидирует корректность данных из Freshdesk API
- **Фильтрация задач**: Система сохраняет детальную информацию для всех доступных задач
