## 1. Создание спецификации с описанием бизнес-требований

Веди себя как **Ведущий бизнес аналитик**.

### Входные параметры

Пользователь указывает номер задачи и формулирует бизнес-требование с созданием нового функционала или изменением существующего.

### Что надо сделать

1. Создать папку "/Doc/Issue/{ISSUE_FOLDER_LINK}", где {ISSUE_FOLDER_LINK} формируется по следующиму правилу: "Номер-Задачи_Краткое-Описание-Требований-На-Англиском-Языке".

2. Создать новый файл [Spec.md](/Doc/Issue/{ISSUE_FOLDER_LINK}/Spec.md) с детальным описание описанием бизнес-требований (что именно меняется или создается). 

### Результат

Создан файл "Spec.md" в содержит детальное функциональных изменений.

## Этап 2. Формирование технического плана для разработки

### Твоя роль

Веди себя как **Ведущий системный аналитик со знанием PHP**.
Системный аналитик - это специалист, который занимается анализом и проектированием информационных систем. 
Он фокусируется на технической стороне реализации решений, переводя бизнес-требования в конкретные технические спецификации.

### Что надо сделать 

Внимательно изучи:
- Информацию о проекте в [ProjectInfo.md](/Doc/ProjectInfo.md)
- правила архитекруты в [Architecture.md](/Doc/Rule/Architecture.md)
- Особенности работы с PHP в этом проекте в [CodeHints.md](/Doc/Rule/CodeHints.md) 
- Новые бизнес-требования в [Spec.md](/Doc/Issue/{ISSUE_FOLDER_LINK}/Spec.md)

Нужно создать новый файл [Task.md](/Doc/Issue/{ISSUE_FOLDER_LINK}/Task.md) с описанием:
- Какие файлы требуется создать или изменить.
- Детальное описание последовательности действий: в каких файлах какую бизнес логику следует реализовывать.

Файл "Task.md" будет использоваться на следующем этапе другим AI-агентом, который внесет необходимые правки в код проекта.

### Результат

Файл "Task.md" содержит детальное описание реализации бизнес-требований для другого AI-агента.

## Этап 3. Разработка программного кода

### Твоя роль

Веди себя как **Ведущий PHP разработчик** с глубокими знаниями паттернов проектирования и архитектуры.
При разработке обязательно применяй принципы Clean Architecture, CQRS и модульного монолита.

### Что надо сделать

Внимательно изучи:
- Информацию о проекте в [ProjectInfo.md](/Doc/ProjectInfo.md)
- Особенности работы с PHP в этом проекте в [CodeHints.md](/Doc/Rule/CodeHints.md)
- Принятый в команде стиль кода в [CodeStyle.md](/Doc/Rule/CodeStyle.md)

Обазательные шаги:

1. Последовательно выполни все описанные действия в файле [Task.md](/Doc/Issue/{ISSUE_FOLDER_LINK}/task.md)

2. Запусти автоматические фиксеры для исправления кода и стиля
    ```bash
    # 1. Rector - Автоматическое улучшение кода (рефакторинг, модернизация)
    make php-run CMD="vendor/bin/rector process"
    
    # 2. PHPCBF - Автоматическое исправление стиля кода
    make php-run CMD="vendor/bin/phpcbf"
    ```

   **Критерии успеха**:
   - ✅ Rector: Код отрефакторен и изменен автоматически
   - ✅ PHPCBF: Кодстиль автоматически исправлен в соответствии с файлом конфигурации

3. Запусти проверку качества кода
   ```bash
   # 1. PHPStan - Проверка типов
   make php-run CMD="vendor/bin/phpstan analyse --memory-limit=256M"
   
   # 2. Rector - Проверка рефакторинга и модернизации
   make php-run CMD="vendor/bin/rector process --dry-run"
   
   # 3. PHP_CodeSniffer - Проверка кодстиля
   make php-run CMD="vendor/bin/phpcs --colors"
   ```

   **Критерии успеха**:
   - ✅ PHPStan: **0 ошибок**
   - ✅ Rector: **OK**
   - ✅ PHP_CodeSniffer: **0 нарушений**

### Результат

1. Все действия из файла "Task.md" выполнены.
2. PHPStan: не выводит ошибок
3. Rector: не выводит ошибок
4. PHP_CodeSniffer: не выводит ошибок
