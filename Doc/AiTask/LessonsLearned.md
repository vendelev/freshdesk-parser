# Уроки, извлеченные из выполнения задач по Domain Layer

## Проблемы, с которыми столкнулся ИИ:

1. **Ошибки PHPStan в тестах**
   - Причина: PHPStan обнаружил "Dynamic call to static method" в тестах
   - Решение: Это не критично для работоспособности кода, но можно улучшить
   - Рекомендация: Использовать статические вызовы методов PHPUnit (
      self::assertTrue вместо $this->assertTrue,
      self::assertFalse вместо $this->assertFalse,
      self::assertSame вместо $this->assertSame,
      self::assertNull вместо $this->assertNull,
      self::assertEquals вместо $this->assertEquals,
     )

2. **Предупреждения PHP_CodeSniffer о длине строк**
   - Причина: Некоторые строки превышают 120 символов
   - Решение: Разбить длинные строки на несколько строк или сократить
   - Рекомендация: Следить за длиной строк при написании кода

3. **Предупреждение о возможном бесполезном переопределении метода**
   - Причина: В исключении InvalidTicketDataException было переопределение метода без изменений
   - Решение: Удалить ненужное переопределение метода
   - Рекомендация: Не переопределять методы без изменения логики

4. **Ошибки форматирования кода**
   - Причина: После удаления методов остались пустые строки, нарушающие стандарты кодирования
   - Решение: Убедиться, что файлы соответствуют стандартам из файла конфигурации после всех изменений
   - Рекомендация: Всегда проверять форматирование кода после внесения изменений

## Рекомендации по улучшению для следующих итераций:

1. **При написании тестов:**
   - Использовать статические вызовы методов PHPUnit (self::assertEquals, self::assertTrue и т.д.)
   - Это устранит ошибки PHPStan и улучшит читаемость кода

2. **При написании кода:**
   - Следить за длиной строк (не более 120 символов)
   - Разбивать длинные строки на несколько строк для улучшения читаемости
   - Не переопределять методы без изменения логики
   - Всегда проверять форматирование кода после внесения изменений

3. **При работе с ValueObjects:**
   - Добавлять реализацию Stringable для лучшей читаемости
   - Использовать типизированные константы для улучшения type safety

4. **При работе с Entity и DTO:**
   - Использовать публичные readonly свойства вместо геттеров (согласно возможностям PHP 8.5)
   - Добавлять типы массивов в PHPDoc комментариях для улучшения анализа кода

5. **При работе с интерфейсами:**
   - Удалять лишние @return void из PHPDoc комментариев
   - Следить за корректностью описания методов

Этот файл должен быть проверен и обновлен после каждой итерации выполнения задач для непрерывного улучшения процесса разработки с ИИ.
